## 問いと分析の要約

### 構想: 2 層のスキル体系

- **メタスキル**: 活動をまたいで不変な scaffold の「文法」。特定の活動のやり方ではなく、やり方の*作り方*（Christopher Alexander のパターン言語と同型 —— 抽象パターンは具体設計を無限に導出するが、それ自体はどの建物でもない）
- **導出**: 個別活動に出会ったとき、活動固有の「語彙」を抽出して文法に充填する手続き

### 不変（文法）と活動固有（語彙）の分離

scholarly-agent-skills の構成要素を分類すると:

| 不変（文法） | 活動固有（語彙） |
| :--- | :--- |
| ゲート（品質の機械検査） | 何を検査するか（用語揺れ・出典・節番号…） |
| SoT（正本の一元化） | 概念モデル・文献 matrix |
| ハンドオフ（文脈のセッション間継続） | 未解決論点の中身 |
| ブリーフィング（理解の scaffold） | 章の目的・確認質問 |
| トリアージ（要修正/要確認/対応不要） | 既知パターン表 |
| 免責・答え責任の宣言 | 研究倫理・IRB 等 |

右列が空欄の「文法だけのスキル」がメタスキルの姿。`create-skill` と `friction-driven-skill-improvement` はメタスキルの萌芽として既に存在する。

### 制約（jiatama-supremacism の枠組みから）

- **可行性の軸**: 品質基準をゲートにコンパイルできる活動ほど導出が効く。検査不可能な活動（暗黙知が中核のもの —— Polanyi）では導出スキルは助言止まり。導出手続きの第一歩は「この活動は scaffold 可能か」の査定ゲート
- **パイドロスの第2批判（275d–e）**: 導出スキルは手続きの外観（「知恵の外観」）を与えうる。対策は生成（導出）と理解（ブリーフィング）の組対設計 —— スキル導出のたびに活動のブリーフィングも同時導出する
- **答え責任は再帰の底でも人間に残る**: 高リスク活動で導出スキルが人をミスリードしても、答えるのはメタスキルではなく人間。「この活動にスキルを適用してよいか」の採否は外部化不可能（本稿 §6.2 の再帰的適用）
- **転移の懐疑論**: 「新しい活動に早く取り組める」は遠隔転移の主張であり、Perkins & Salomon 系の懐疑的文献がある（転移は自発的には滅多に起きない）。研究テーマ化するなら「導出スキルは転移を促進するか」が実証の的

## 軽量オントロジーモデリングとの接続（2026-08-20 著者提案）

**「人間の活動をオントロジーとして記述すれば、活動に含まれる概念を整理できるのではないか」** —— これは導出手続きの「語彙抽出」ステップそのものであり、`lightweight-ontology-modeling`（cursor-templates）がそのままエンジン候補になる。

### 同スキルが scaffold 設計パターンの実例であること

- 核心原則「**人間はビジネスの言葉で答える。AI が概念・関係に変換する**」は、種①（線引き基準）の判断分業パターンと同型（ブリーフィングの TERM/VALID/MAP と同じ）
- 「人間検証は省略禁止」（§4.3・§4.4・§8「機械抽出だけで完成にする」は落とし穴）—— 答え責任が設計に内蔵されている
- Gruber (1993) の定義（「共有された概念化の明示的仕様」）に照らすと、オントロジー化とは活動の概念化を**共有可能＝教え可能＝ scaffold 可能**にする操作である

### 活動一般への一般化で読み替えが必要なもの

| ソフトウェア開発（現行） | 人間の活動一般 |
| :--- | :--- |
| サービス | 参加者・役割・道具（AI を含む） |
| domain-model.md（第一入力） | 手順書・教材・観察記録・熟練者インタビュー |
| コード・ER図からの機械抽出 | 活動にはコードが無い → 観察・インタビューが主軸になる（§4.4「暗黙知の欠落」の限界はさらに大きい） |
| コンテキストマップ（どのサービスが概念を所有するか） | 誰が・どの道具が、どの判断・成果物の SoT を持つか（＝線引き基準の適用場所） |

### 限界の指摘

オントロジーは「その活動に**何が**あり、どう関係するか」（対象の地図）を記述するが、「**何が良いか**」（品質基準＝ゲート）は別層である。導出手続きは最低でも、オントロジー（対象の地図）→ ゲート（基準の地図）→ ブリーフィング（理解の地図）の 3 層を必要とする。`scholarly-concept-modeling`（学術概念の DDD 的型定義）は同学の論文執筆版インスタンスとして既に存在する。

## 3 つの種の統合（2026-08-20 確定の構図）

- **種①（線引き基準の汎用化）** = 理論: 何が外部化可能か
- **種③（本メモ = メタスキル）** = 方法: 外部化可能な部分からスキルを導出する（導出の第一歩＝種①の線引き判定）
- **種②（ループエンジニアリング。`loop-engineering-multi-paper-idea.md`）** = 運用: 導出スキルを人間の採否を律速として回す

①→③→② の依存順。1 つの研究プログラムの両翼+中核として構造化できる。

## 研究テーマ化の構図（候補）

- 研究問いの例: 「人間の活動の scaffold を活動横断の文法と活動固有の語彙に分離したとき、語彙抽出（軽量オントロジー化）からのスキル導出は、新規活動への適応を促進するか」
- 接続先の錨: Wood, Bruner & Ross (1976)（scaffolding 原論 —— fading を伴う教師の自動生成という構想の照合先）、Vygotsky（ZPD）、Salomon & Perkins（cognitive tools／転移懐疑論）、Gruber (1993)（オントロジー定義）、Alexander（パターン言語）、Gregor & Hevner（デザイン理論 —— DSR としての貢献の型）—— いずれも引用時は一次照合必須
- 検証の存在例（DSR 的）: ソフトウェア開発・学術執筆以外の**第三の活動**を 1 つ選び、メタスキル草案から導出を試みて有効性を観察する
