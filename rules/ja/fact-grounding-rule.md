# 厳格なファクト・グラウンディングルール (Strict Fact-Grounding & Repository Evidence Rule)

## 概要
AI エージェントによる学術論文執筆時のハルシネーション（記憶・内部ナレッジによる数値や事実の捏造）を原理的に防ぐため、論文本文に記述されるすべての主張・数値・引用について、**「インターネットまたは公式調査資料経由での一次情報取得」** と **「リポジトリ内データファイルとしての実体化」** を義務付けるルールである。

---

## 🚫 1. 内部知識・記憶のみに基づく記述の絶対禁止
- LLM の学習データ（内部ナレッジ）のみに依拠して、統計数値、年号、固有名詞、調査結果、文献の主張を本文（`docs/chapters/`）に記述することを厳禁とする。
- 根拠なしに「〜〜という調査結果がある」「〜〜%とされる」等の文章を出力してはならない。

---

## 🌐 2. インターネット経由でのリアルタイム一次情報取得の義務
- 論文内で引用・使用するすべての情報は、執筆中または調査フェーズにおいて、以下のいずれかの手段を用いて直接取得されたものでなければならない：
  1. **Web検索ツール / URL閲覧ツール**: 公式Webサイト・公刊レポートのリアルタイム検索および閲覧
  2. **オープンデータ API スクリプト (`fetch_macro_data.py` 等)**: 世界銀行等の公式オープンデータ API からのリアルタイム取得
  3. **PDF解析ツール (`convert_pdf_to_markdown.py` 等)**: 学術論文PDFのダウンロードと構造化テキスト変換
  4. **手動調査データインベントリ**: オフライン環境や契約データベース（JSTOR等）から研究者が手動取得した検証可能な資料

---

## 📂 3. リポジトリ内へのデータ実体化（Data Grounding）の義務
- 取得した一切の情報は、必ずリポジトリ内の以下の場所に実体ファイルとして保存する（※Gitリポジトリへのコミットはユーザーの承認に基づき行う）：
  - **`docs/data/`**: 取得した統計数値、時系列テーブル、指標データセット (`*.md`, `*.csv`, `*.json`)
  - **`docs/literature/`**: 文献マトリクス、先行研究ギャップ報告書、論文解読ノート (`*.md`)
- **参照の一致**: 本文（`docs/chapters/`）で記述されるすべての数値や事実には、必ず上記リポジトリ内ファイルへの参照・出典リンクを紐付けなければならない。

---

## 🔢 4. 算式・原数値アンカールール (Quantitative Evidence & Calculation Anchor Rule)

算出数値（比率・倍率・変化幅・成長率・格差等）を本文に記述する場合、以下の3条件を満たさなければならない：

1. **【必須・本文】即時学術出典アノテーション**: 算定数値の初出段落に、標準的な学術引用スタイル（例: `(PSA, 2024)`、`[^1]`）の出典マーカーを付与する。
   - ⚠️ **重要（出力境界）**: 論文本文（`docs/chapters/`）の引用カッコ内に、リポジトリのローカルファイルパス（`data: docs/data/...`）を直接印字してはならない。ローカルパスは設計ドキュメント・エビデンス報告書（`docs/design/`）でのみ管理する。
2. **【選択・記録】原数値・算式の保持**: 算出数値の基となった原数値（分子・分母・基準年等）および算出ロジックを、本文・脚注・または `docs/data/` 内のデータテーブル（例: `<!-- tbl-1 -->`）のいずれか1箇所以上に明記する。
3. **【必須・禁止】出所不能数値の出力禁止**: `docs/data/` または一次文献から根拠を特定・再現できない数値（出所を特定できない数値）を本文に出力することを厳格に禁止する。

---

## ⚠️ 5. 違反時の動作（ビルドブロック）
- リポジトリ内に実体ファイル（`docs/data/` または `docs/literature/`）が存在しない状態で本文に数値やファクトが検出された場合、AI エージェントは即座に執筆を中断し、以下のいずれかを実行しなければならない：
  1. ネット検索・API実行・手動データ登録により一次情報を取得し、`docs/data/` または `docs/literature/` に実体ファイルを生成する。
  2. 実体データが取得できるまで該当記述を保留・修正する。
