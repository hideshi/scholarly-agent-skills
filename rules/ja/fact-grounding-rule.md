# 厳格なファクト・グラウンディングルール (Strict Fact-Grounding & Repository Evidence Rule)

## 概要
AI エージェントによる学術論文執筆時のハルシネーション（記憶・内部ナレッジによる数値や事実の捏造）を原理的に防ぐため、論文本文に記述されるすべての主張・数値・引用について、**「インターネットまたは公式調査資料経由での一次情報取得」** と **「リポジトリ内データファイルとしての実体化」** を義務付けるルールである。

---

## 🚫 1. 内部知識・記憶のみに基づく記述の絶対禁止
- LLM の学習データ（内部ナレッジ）のみに依拠して、統計数値、年号、固有名詞、調査結果、文献の主張を本文（`docs/chapters/`）に記述することを厳禁とする。
- 根拠なしに「〜〜という調査結果がある」「〜〜%とされる」等の文章を出力してはならない。

---

## 🌐 2. 情報取得の二段階モデル（Discovery / Grounding）

論文内で引用・使用する情報は、用途に応じて以下の2段階に分離しなければならない。

### 2-A. 探索（Discovery）— 引用根拠として不十分
- **WebSearch / 検索スニペット / エージェント内部知識**: 文献候補の同定・DOI/arXiv ID 確認のみに使用可。**学術文献の「内容に関する主張」（何を示したか・何を主張したか）の根拠として使用禁止**。
- **例外（非学術文献）**: 政府・国際機関等の**公式ページ自体が一次情報**である統計・制度事実は、WebFetch による当該公式ページの直接閲覧をもって Grounding とみなす（§2-B 相当）。
- **許可ツール**: `search_literature.py`（候補同定）、WebSearch（書誌メタデータ確認のみ）

### 2-B. 実体化（Grounding）— 引用根拠として必須
学術文献を本文（`docs/chapters/`）で引用する場合、以下のいずれかにより **`docs/<paper-id>/literature/papers/*.md`** を生成しなければならない：
  1. **PDF解析ツール (`convert_pdf_to_markdown.py` 等)**: 学術論文PDFのダウンロードと構造化テキスト変換
  2. **arXiv / OA 全文取得**: 全文テキストのダウンロードと Markdown 化
  3. **手動文献 stub (`status: manual-stub`)**: 書籍・学位論文等、PDF 自動取得不可の文献について、ページ番号付き手動書き抜きを frontmatter 付き Markdown として保存（§2-4 手動調査データインベントリと接続）
  4. **オープンデータ API スクリプト (`fetch_macro_data.py` 等)**: 統計・数値主張用（`docs/data/` へ保存）

> **Invariant**: `literature-matrix.md` は索引（Discovery 成果物）であり、**引用根拠としては使用不可**。引用根拠は `literature/papers/*.md` または `docs/data/` の実体ファイルに限る。

---

## 📂 3. リポジトリ内へのデータ実体化（Data Grounding）の義務
- 取得した一切の情報は、必ずリポジトリ内の以下の場所に実体ファイルとして保存する（※Gitリポジトリへのコミットはユーザーの承認に基づき行う）：
  - **`docs/data/`**: 取得した統計数値、時系列テーブル、指標データセット (`*.md`, `*.csv`, `*.json`)
  - **`docs/literature/literature-matrix.md`**: 文献候補一覧・ギャップ分析（**索引のみ。引用根拠として不可**）
  - **`docs/literature/papers/*.md`**: 一次文献テキスト（ingestion 成果物。**学術文献引用の根拠**）
- **参照の一致**: 本文（`docs/chapters/`）で記述されるすべての数値や事実には、必ず上記リポジトリ内ファイルへの参照・出典リンクを紐付けなければならない。

---

## 🔢 4. 算式・原数値アンカールール (Quantitative Evidence & Calculation Anchor Rule)

算出数値（比率・倍率・変化幅・成長率・格差等）を本文に記述する場合、以下の3条件を満たさなければならない：

1. **【必須・本文】即時学術出典アノテーション**: 算定数値の初出段落に、標準的な学術引用スタイル（例: `(PSA, 2024)`、`[^1]`）の出典マーカーを付与する。
   - ⚠️ **重要（出力境界）**: 論文本文（`docs/chapters/`）の引用カッコ内に、リポジトリのローカルファイルパス（`data: docs/data/...`）を直接印字してはならない。ローカルパスは設計ドキュメント・エビデンス報告書（`docs/design/`）でのみ管理する。
2. **【選択・記録】原数値・算式の保持**: 算出数値の基となった原数値（分子・分母・基準年等）および算出ロジックを、本文・脚注・または `docs/data/` 内のデータテーブル（例: `<!-- tbl-1 -->`）のいずれか1箇所以上に明記する。
3. **【必須・禁止】出所不能数値の出力禁止**: `docs/data/` または一次文献から根拠を特定・再現できない数値（出所を特定できない数値）を本文に出力することを厳格に禁止する。

---

## ⚠️ 5. 違反時の動作（ビルドブロック）
- リポジトリ内に実体ファイルが存在しない状態で本文に数値・ファクト・**学術文献引用**が検出された場合、AI エージェントは即座に執筆を中断し、以下のいずれかを実行しなければならない：
  1. ネット検索・API実行・PDF ingestion・手動 stub 登録により一次情報を取得し、`docs/data/` または `docs/literature/papers/` に実体ファイルを生成する。
  2. 実体データが取得できるまで該当記述を保留・修正する。
- **学術文献引用の判定**: `python3 scripts/check_literature_grounding.py` が FAIL を返した場合、該当章/節の執筆・追記をブロックする（WARN は執筆継続可だが claim-evidence-gate 前に full-text 化を推奨）。
- **ゲートは `papers/*.md` を正本とする**: PDF は `.gitignore` 可。判定は Markdown frontmatter と本文テキスト長に基づく（CI/クリーンクローンでも再現可能）。
